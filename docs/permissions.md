# 首次使用与权限

第一次打开正式的 `freetalk.app`，点击「开始设置」，先完成权限，再下载模型和试说。应用不会在启动时连续弹出全部权限请求；每项都由你主动点击。

| 权限 | 用途 | 怎么开启 |
| --- | --- | --- |
| 麦克风 | 录制你主动开始的语音 | 点击「允许麦克风」，在系统弹窗点「允许」。拒绝过时，点击「打开麦克风设置」，在系统设置 → 隐私与安全 → 麦克风中打开 freetalk。 |
| 辅助功能 | 获取当前输入位置并写入草稿 | 点击「打开辅助功能设置」，在隐私与安全 → 辅助功能中打开 freetalk。列表没有应用时点「+」添加当前使用的 freetalk.app；引导中的「在访达中显示本应用」可以定位它。 |
| 输入监控 | 检测你设置的全局快捷键 | 点击「打开输入监控设置」，在隐私与安全 → 输入监控中打开 freetalk。快捷键关闭时，按钮会改成「启用快捷键」。 |

应用以**事件监听是否真正创建成功**为准，而不是只看系统开关。快捷键使用的活动事件监听要求辅助功能权限，输入监控是否生效则由系统在创建监听时判断。系统设置里的开关已打开、应用却仍显示未生效时，通常是旧授权记录没有匹配当前二进制。

Touch ID、密码和系统授权确认由你操作。返回 freetalk 会自动检查状态，也可以点击「我已设置，重新检查」。若系统要求退出并重新打开，照系统提示操作；引导会记住当前步骤。

部分新版 macOS 把原「辅助功能」授权页显示为「设备控制和数据访问」。在这种界面下，请到隐私与安全中的该页面查找 freetalk；它对应本应用检查的跨应用控制权限。

只允许麦克风时，可以选择「先只用麦克风」，准备模型后在引导中试说。此时不会显示为跨应用输入已就绪。结束引导选择应用内使用后，不会每次启动都要求其余权限；以后可从菜单「权限设置引导」继续开启。

权限被设备管理策略限制时，界面会明确提示，应用不能绕过限制。事件监听未连接时，可以先点「重新连接快捷键」；仍失败时退出并重开应用，或按下面的签名失配步骤处理。取消授权后，真实状态会重新显示。

## 自定义快捷键与测试

设置 → 语音输入 → 「快捷键」：

- 点击「语音输入」或「会议录音」后的快捷键按钮，按下新的按键即可录制。轻按单个修饰键（左右 Option / Command / Shift / Control、Fn）或按住修饰键再按其他键。
- Esc 取消录制；「恢复默认」回到右 Option 和右 Option + M。
- 会议键默认跟随语音键（主键 + M）。取消「会议键跟随语音键」后可以单独录制；主键是组合键时，会议键回退为右 Option + M。会议键必须是组合键。
- 录制期间全局快捷键暂停，按键不会触发录音；切换到其他应用会自动取消录制。
- 与另一快捷键重复、无修饰键的字母/数字、单独 Esc 会被拒绝；Cmd + Space、Ctrl + Space 等系统组合会提示冲突，但仍可保存。
- 「测试快捷键」进入 8 秒监听，不录音、不插入文字。它会区分：监听未启动（权限/签名问题）、收到事件但不匹配（绑定问题）、匹配成功、8 秒内完全没有事件（可能被其他应用占用）。

## 更新应用后

源码构建默认使用 ad-hoc 签名，每次构建的 CDHash 都会变化，macOS 可能把更新后的应用当作新应用，旧授权记录不再匹配。正式发布包同样未做 Apple 公证。正式应用的名称是 freetalk，最低构建目标为 Apple Silicon / macOS 14；测试用 Preview 程序不属于安装包。

本地开发可以运行：

```sh
bash scripts/setup-local-signing.sh
```

它会创建一个自签名代码签名身份 `freetalk Local Signing`，之后 `scripts/build.sh` 自动使用。这样本地重建的 designated requirement 保持不变，辅助功能、输入监控和麦克风授权可以跨构建保留。首次切换到该身份后仍需重新授权一次。

这把私钥签出的任何程序都会继承 freetalk 已获得的系统权限。脚本把证书信任限制在代码签名用途，私钥导入后不可导出，只允许 `codesign` 使用。不再需要时，在钥匙串访问的「登录」钥匙串中删除 `freetalk Local Signing` 证书及其私钥。发布流程（`scripts/publish-release.py`）始终不使用本地身份。

如果系统设置的开关已经打开，应用仍显示「尚未允许」或「授权记录可能已失效」：

1. 先退出并重新打开 freetalk，再检查状态。
2. 若仍未生效，在对应权限页选中 freetalk，用「−」移除它的旧条目，再用「+」添加当前安装的 freetalk.app，并开启开关。「在访达中显示本应用」能定位正在使用的版本，避免选到旧备份。
3. 输入监控若提示「退出并重新打开」，按提示重开。回到应用检查麦克风、辅助功能和快捷键的实际状态。

这一流程修复的是旧授权记录与更新后的签名不匹配的情况。直接再次添加同名应用，可能继续保留旧记录；仅重开应用也不能修正签名失配。操作只针对 freetalk 的条目，Touch ID 或密码由本人确认。

本应用不修改系统隐私数据库，也不要求关闭系统安全功能。

# 验证记录

2026-11-04，freetalk 0.2.0，Apple M4 / 16 GB / macOS 27.0。以下是单机验证，不是模型排行榜或跨设备性能保证。

## 本地安装

- 从空目录下载独立 uv、Python 3.11.14、固定版本依赖和两个模型。未复用既有模型文件。
- 两个模型下载合计 3,289,740,931 字节，逐文件 SHA-256 校验成功。
- `uv pip check` 确认 41 个依赖包兼容；公开仓库的安装器再次校验完整模型并成功写入配置。
- 应用源码构建、安装和代码签名检查通过；使用本地 ad-hoc 签名，未做 Apple 公证。
- 在已安装的应用中检查了首次引导、模型就绪状态，以及麦克风、辅助功能、输入监控三项权限状态。

## 真实模型回放

使用 macOS Tingting 离线生成的合成语音：

> 呃，先用十个样本，不对，改成十二个。保留所有日志。

转换为 16 kHz 单声道 16 位 PCM WAV，时长 5.59 秒。退出应用后，使用上面全新安装的 Python 与模型执行 `scripts/smoke-models.py`，实际调用 ASR 和整理模型：

| 项目 | 本次结果 |
| --- | --- |
| ASR 原稿 | 呃，先用十个样本。不对，改成十二个，保留所有日志。 |
| 整理结果 | 先用12个样本，保留所有日志。 |
| 整理模型实际调用 | 是，检测到改口 |
| ASR 耗时 | 0.34 秒 |
| 整理耗时 | 2.11 秒 |
| 输入音频后的总处理时间 | 2.44 秒 |
| 新进程加载模型 | 15.36 秒，不计入上面的处理时间 |
| MLX 报告的峰值内存 | 约 4.55 GB，不代表整个系统的内存占用 |

这是一次回放测量，不包含物理麦克风、录音设备启动、跨应用输入或用户交互耗时，也没有刻意清空系统文件缓存。应用会常驻模型，但不应把这一个样例的处理时间当作所有录音的延迟。

回放暴露了一个数量改口问题：模型用“十二个”替换“十个样本”时会漏掉“样本”。现已对这种有原文证据的数量省略补全原对象，保留后续指令；明确改成“十二个文件”时仍保留新的对象。

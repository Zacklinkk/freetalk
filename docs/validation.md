## 2026-11-05：0.2.1 整理边界修复

在同一台 M4 / 16 GB Mac 上，对 22 条原稿或转写文本进行真实本地整理模型回放。检查范围包含漏标点的改口、相连的纠正信号、短重复起头、条件、否定、引用、强调以及没有给出替代内容的改口；这不是独立盲测或 ASR 准确率统计。

合成检查示例：

| 输入 | 输出 |
| --- | --- |
| 预算800元不对，改成900元。记录，记录所有支出。 | 预算900元。记录所有支出。 |
| 联系小林不对，改为小张。附上，附上说明。 | 联系小张。附上说明。 |
| 别删，别删缓存目录。 | 别删缓存目录。 |
| 先保存草稿，再保存附件。 | 原样保留 |
| 准备六份合同。不对，先等等。 | 准备6份合同。不对，先等等。并提示仍有未解决的改口 |

其中 18 条实际调用小模型，单次整理耗时 0.76–2.64 秒，中位数 1.63 秒；其余 4 条走快速规则。每条至多一次整理模型调用，加载模型的时间不包含在这些数值中。新增路径不会让所有短句都调用模型，但疑似短重复会增加一次必要的检查。

98 项 Python 测试、7 组 Swift 检查及应用构建通过。旧版引导只保留最后一次结果，且不保存音频，所以无法复原此前全部试说，也无法凭文字确认声学数量误识别。本轮文字回放不能替代更新后新的物理麦克风试说；ASR 原稿中的错误数量不会被偷偷改成练习题答案。

## 真实模型回放

使用 macOS Tingting 离线生成的合成语音：

> 呃，先用十个样本，不对，改成十二个。保留所有日志。

转换为 16 kHz 单声道 16 位 PCM WAV，时长 5.59 秒。退出应用后，使用上面全新安装的 Python 与模型执行 `scripts/smoke-models.py`，实际调用 ASR 和整理模型：

| 项目 | 本次结果 |
| --- | --- |
| ASR 原稿 | 呃，先用十个样本。不对，改成十二个，保留所有日志。 |
| 整理结果 | 先用12个样本，保留所有日志。 |
| 整理模型实际调用 | 是，检测到改口 |
| ASR 耗时 | 0.34 秒 |
| 整理耗时 | 2.11 秒 |
| 输入音频后的总处理时间 | 2.44 秒 |
| 新进程加载模型 | 15.36 秒，不计入上面的处理时间 |
| MLX 报告的峰值内存 | 约 4.55 GB，不代表整个系统的内存占用 |

这是一次回放测量，不包含物理麦克风、录音设备启动、跨应用输入或用户交互耗时，也没有刻意清空系统文件缓存。应用会常驻模型，但不应把这一个样例的处理时间当作所有录音的延迟。

回放暴露了一个数量改口问题：模型用“十二个”替换“十个样本”时会漏掉“样本”。现已对这种有原文证据的数量省略补全原对象，保留后续指令；明确改成“十二个文件”时仍保留新的对象。

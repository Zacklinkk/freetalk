干净转写样例涵盖数量改口、全部日志保留、提议与决定区别、负责人/期限、发布前提、预算、专业术语以及引用的测试命令。增加结构检查以避免“回退全部原文也通过关键词检查”被误报为整理成功。逐字引用有效和脑图结构覆盖不是语义准确率，仍需结合原稿核对分类与遗漏。

## 2026-11-05：0.2.1 整理边界修复

在同一台 M4 / 16 GB Mac 上，对 22 条原稿或转写文本进行真实本地整理模型回放。检查范围包含漏标点的改口、相连的纠正信号、短重复起头、条件、否定、引用、强调以及没有给出替代内容的改口；这不是独立盲测或 ASR 准确率统计。

合成检查示例：

| 输入 | 输出 |
| --- | --- |
| 预算800元不对，改成900元。记录，记录所有支出。 | 预算900元。记录所有支出。 |
| 联系小林不对，改为小张。附上，附上说明。 | 联系小张。附上说明。 |
| 别删，别删缓存目录。 | 别删缓存目录。 |
| 先保存草稿，再保存附件。 | 原样保留 |
| 准备六份合同。不对，先等等。 | 准备6份合同。不对，先等等。并提示仍有未解决的改口 |

其中 18 条实际调用小模型，单次整理耗时 0.76–2.64 秒，中位数 1.63 秒；其余 4 条走快速规则。每条至多一次整理模型调用，加载模型的时间不包含在这些数值中。新增路径不会让所有短句都调用模型，但疑似短重复会增加一次必要的检查。

98 项 Python 测试、7 组 Swift 检查及应用构建通过。旧版引导只保留最后一次结果，且不保存音频，所以无法复原此前全部试说，也无法凭文字确认声学数量误识别。本轮文字回放不能替代更新后新的物理麦克风试说；ASR 原稿中的错误数量不会被偷偷改成练习题答案。

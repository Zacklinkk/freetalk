# 数据、上下文与改字学习

## 哪些数据被读取

录音由用户主动触发。应用可以提前准备设备节点和格式，但没有开始录音时不安装录音 tap，也不启动音频引擎采集。录音期间音频仅在内存中流向本机模型，不保存音频文件。

启用输入框上下文时，开始录音后通过辅助功能 API 冻结当前目标，最多使用开头 500 字、光标前 1,000 字、光标后 500 字和选中的文字（最多 2,000 字）作为辨词背景，另外记下应用名、窗口标题和网页的域名（不含路径和参数）。它不遍历其他窗口或读取整段聊天历史，不把剪贴板作为模型上下文。密码框不作为正常输入目标。

「参考输入框周围的可见文字」单独开启，只在录音开始时读取目标窗口里辅助功能能读到的文字，最多 4,000 字。很多 Electron、画布和远程桌面窗口读不到文字；再开启「识别窗口里的文字」后，可见文字少于 200 字时，用 macOS 的文字识别（Vision）读一次目标窗口的画面。这需要“屏幕录制”权限；截取的画面只在内存里用于识别，不保存、不上传，识别出的文字和可见文字一样只给本机模型辨词，也不会因为它们而把近音词提示发给云端。1Password、Bitwarden、钥匙串访问等密码管理器的窗口不读取。

可见文字和识别出的文字只用来辨认同音、近音的人名和术语（例如屏幕上写着“夏普比率”，口述识别成“下普比率”），不会加进你的文字。语气、改口和数字的处理与没有上下文时相同。

插入前重新核对目标、草稿内容和选区。不能确认目标时，结果保留在文字历史供手动复制。模型输出不被当作可执行命令。

## 常用词怎么生效

词库最多 200 个词，每次录音冻结一份。当前输入框实际出现的词优先，最多 48 个词作为 ASR 提示；整理模型也可以用这些已知拼写作局部辨词参考。只合并有依据的大小写或英文缩写，不把所有相近发音都改成词库词。

## 从改字中学习

成功插入后，开启学习时，仅观察同一输入框中本次插入区域附近的修改：至少 90 秒，每次改字后再等 30 秒，最长 10 分钟。离开输入框、切换应用或开始下一次录音就停止。富文本输入框把粘贴的列表显示成自己的样子（文字里没有“1.”，或换成它自己的编号），这不算你的修改，学习从输入框实际显示的文字开始。

短词修改稳定约 1.5 秒后，程序检查词边界、近音/拼写、数字和否定变化。中文要求字数相同、拼音相同或只差一个字母，口音造成的 z/zh、c/ch、n/l、an/ang 差别也算；他/她、的/地/得这类用字选择不学。符合条件的修正保存为候选关系，并把正确拼写加入词库，显示 5 秒可撤销提示。标点调整、整段改写、数量变化或意图反转不当作词语学习。撤销恢复此次记录与新增词。

改字之外，删掉整理留下的口水词（句首的“就是”、开头的“然后”、“那个，”）、补回被整理删掉的语气词、去掉或补上句末句号、在“但是、所以”等连接词前加逗号、在中文和英文之间加或去空格，会记成**整理习惯**（`style-lessons.json`，最多 100 条，只有你的账户可读写）。习惯只做这几类固定的小改动，不改写内容：删除和改动类的习惯第二次出现才生效，一次偶然的修改不改变什么；补回的词立即保留，之后整理不再删它。语气词和句号按应用类别分别记录（聊天里去掉句号，不影响邮件）。约一个月没再出现会淡出，反方向的修改会让它失效；生效时显示 5 秒可撤销提示，也可以在「管理已学会的词和习惯」的「整理习惯」页移除。

识别听错的词按上面的方式学习。整理写错或该删没删的地方不学成词对：每次观察结束时，本次的原稿、插入的整理结果和你改后的文字记在 `cleanup-feedback.json`（最多 60 条，可在设置中清除；关闭改字学习就不记录）。在「常用词与学习 → 专业配置 → 整理规则优化」里，你可以把这些记录和现有整理规则发给云端的强模型，由它总结最多 10 条整理偏好。本机先用新旧规则分别重跑这些记录、近期没改过的口述和内置整理测试集（`evals/cleanup-cases.json`）：没有记录离你改后的文字变远、没改过的口述结果不变、测试集没有以前通过现在不通过的条目，就自动写入 `cleanup-preferences.json` 并生效；否则显示变化和变差的条目，由你决定是否仍然采用。随时可以恢复默认规则。开启「夜间整理」里的“整理规则优化”后，每晚有新记录时自动运行一次，按同样的条件决定是否采用（见下一节）。整理偏好达到 8 条时，强模型改为把它们并入整理规则，生成一份新的规则全文，同样先过这些检查；采用后新规则保存在 `prompts/edit-rules.txt`，之前手动修改过的版本备份在 `prompts/backups/`（每个文件保留最近 10 份），可以在「整理提示词」里查看或恢复默认。偏好只追加在内置规则之后，原有的保留规则和安全检查不变。

## 夜间整理

「常用词与学习 → 夜间整理」是一个总开关，下面两项可以分别开关，都使用云端的强模型：

- **画像与转写热词**：口述满 20 条后，本机先统计历史里反复出现的词（英文词按原样，中文词用 macOS 的分词；至少出现在 3 次口述里，去掉“我们、一下”这类日常词），只把最多 150 个词和它们出现的次数发给强模型，不发送句子和音频。强模型据此推断你常谈的领域（最多 5 个），列出这些领域里语音识别容易写错的词（最多 40 个，例如 benchmark、SFT、LoRA），保存在 `user-profile.json`（只有你的账户可读写）。这些词排在个人词库和学过的纠正之后，填进语音识别剩下的热词位置（口述共 48 个），会议转写也会用到；它们只影响识别，不直接改写文字，也不交给整理模型。之后每多 10 条口述，夜间整理重新生成一次；可以随时清除画像，关闭这一项后识别不再使用这些词。
- **整理规则优化**：同上一节，每晚有新的改字记录时运行一次。

每晚 00:30–06:00 之间、15 分钟没有口述时运行一次，结果显示在卡片上；「立即运行」会马上执行已开启的步骤。为了不在夜里弹出钥匙串授权，当天启动后没有读到过密钥就跳过。

**这不是字符串替换表，也没有训练模型权重。** 错词关系供回看、撤销和约束，正确词提供软提示。正常的旧词仍然允许被识别出来；没有本次语音/原稿证据时，整理层不能强行套用历史同音纠正。当前没有实现积累音频标注或 LoRA 微调，因为默认根本不保留音频。

## 按应用调整语气

「语音输入 → 专业配置 → 按应用调整语气」可以给聊天、工作沟通、邮件、文档、笔记、AI 助手、社交、任务与项目、其他网页和其他应用分别选一种语气。自然（默认）按现在的方式整理；正式去掉句末的呀、啦、哈、呗、咯、嘞、哦，结尾补上句号；口语保留语气词，一句话的消息不加句号。语气只是整理后的几条固定规则，不让模型改写，也不发送到云端。

应用类别来自内置的应用表（约 180 个常用应用的 Bundle ID）和网站表（90 多个域名，同一域名下按路径区分文档、表格和演示文稿）；表里的 ID 都核对过真实应用、Homebrew 的安装信息或其他开源项目的目录，没有猜测。浏览器里按网页域名判断，未收录的应用按名称里的词判断（如 mail、笔记），否则算“其他应用”。应用类别不影响富文本粘贴：列表和分段在所有应用里都同时提供富文本和纯文本，由输入框自己选用，终端和代码编辑器这类只接受纯文本的输入框显示带编号的文本行。

## 查看和修改整理提示词

「语音输入 → 专业配置 → 整理提示词」显示整理模型收到的提示词原文：整理规则、口述整理、整句撤回、各自的示例对话、口水词选择和规则优化。点「检查并保存」时，本机先用当前提示词和修改后的提示词各跑一遍整理测试集，没有变差才保存；变差时列出变差的条目，你仍可以选择「仍然保存」。修改保存在 `prompts/` 子目录（只有你的账户可读写），覆盖应用内置的同名文件；「恢复默认」删除修改。示例必须是 user / assistant 交替的 JSON 数组，空白或无法解析的修改会被拒绝保存；即使文件被手动改坏，整理时也会忽略它，改用内置提示词。已采用的整理偏好仍追加在提示词之后，安全检查不受提示词影响。

## 本地保存

`~/Library/Application Support/freetalk/` 包含配置、最多 500 条文字历史、词库、学习记录和少量启动诊断。文字历史包含原稿、结果、耗时与插入状态，不保存输入框背景。开启改字学习时，历史还记下插入后你改成的文字，以及这次学到了什么（学会的词对、是否记入整理规则优化的样例）或为什么没有学习（例如 90 秒内没有改字、切换了应用）、记下或学会了哪些整理习惯；这些显示在「全部历史」里。超出 500 条时淘汰最旧记录。

数据文件使用本地文件权限限制访问，但没有独立加密。设备诊断包含设备名称、连接类型和阶段耗时，不包含音频或文稿。日志用于错误诊断，分享前仍应人工检查。首次引导试说不写入普通历史；最近 10 次原稿、结果和状态仅保留在应用内存中供回看，退出即清除，不保留音频。

模型安装阶段连接公开的下载站点，仅获取安装工具、依赖和模型；不发送个人转写内容。自动更新检查会连接 GitHub，下载更新也从 GitHub 获取；默认启动时和每天检查，可以在设置中关闭。请求包含常规网络信息（例如 IP 和客户端版本），不发送音频、转写、个人词库或输入框内容；Sparkle 系统信息收集已关闭。项目不包含遥测服务或个人数据自动上传逻辑。

云端模型是可选功能，默认不用。「语音输入 → 专业配置 → 云端模型」里填一个服务（协议、地址、API Key、可选请求头）和两个模型：快模型用于口述整理，强模型用于整理规则优化和会议深度写作（留空则都用快模型），再按功能勾选要用云端的地方。勾选口述整理后，每次需要模型整理的口述会把原稿、输入框文字、应用名、窗口标题和个人词库发送到这个服务；当前窗口的可见文字、以及只在可见文字里出现的近音词提示始终不发送，音频从不上传。快速规则整理不会联网。整理规则优化发送插入后被你改过的记录；会议写作发送本地纪要和引文。API Key 和额外请求头只存在 macOS 钥匙串，不写入设置文件、历史或日志。云端失败时，本次使用本地模型，并在浮窗与历史中标明。
